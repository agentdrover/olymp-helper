# ADR 0001. Архитектура v1

Статус: принято (22.10.2026). Нормативный контракт — `docs/spec/SPEC-1.0.md`; здесь только решения и ссылки на разделы.

## Решения

1. **Приложение: FastAPI + Jinja + HTMX, SQLite в режиме WAL.** Данные и файлы — на томе `/srv/olymp` (SPEC 1.7). Python 3.12.
2. **Два контейнера.** Контейнер приложения и отдельный контейнер-исполнитель модели. CLI моделей запускаются только в исполнителе: без тома с данными, с файловой системой только для чтения, пустым рабочим каталогом, минимальным окружением и исходящими соединениями только к API своего провайдера. Приложение вызывает его по локальному сокету/HTTP (SPEC 1.4). (уточнение по ревью #2013) контейнер-исполнитель свой на каждый канал и держит только его токен; сервер и CLI работают под разными UID; рабочая область CLI — ограниченный tmpfs, очищаемый после каждого запроса; один запуск за раз, общий ключ приложения и исполнителя, неисправность ведёт к перезапуску контейнера; остаточный риск cursor-agent (shell в режиме ask) принят изоляцией и проверяется в OH-T09.
3. **Два канала модели.** Claude CLI (подписка) и cursor-agent (ключ Cursor), общий интерфейс `ModelChannel`, основной канал выбирается в настройках, при ошибке — одна попытка на запасном; дневной лимит запусков с учётом до запуска (SPEC 1.4).
4. **Доступ: домашняя сеть и HTTPS.** Сервис работает на K8 в LAN. Голос требует secure context, поэтому HTTPS: свой корневой сертификат, сертификат сервера с SAN на адрес K8, доверие на ноутбуке ребёнка (SPEC 1.7).
5. **Распознавание речи — локально.** MediaRecorder → ffmpeg → whisper.cpp в образе приложения, без загрузок во время работы; аудио удаляется после распознавания; голос наружу не уходит (SPEC 1.6, 1.7).
6. **Поиск по учебникам — SQLite FTS5** с одинаковой нормализацией для индекса и запроса (SPEC 1.7). Рендер страниц — локально (PyMuPDF).
7. **Секреты** (`CLAUDE_CODE_OAUTH_TOKEN`, `CURSOR_API_KEY`) не попадают в репозиторий, образ, логи и отчёты; доставляются при запуске на K8 задачей проекта home-infra.

## Последствия

- Модель не видит данных ребёнка за пределами переданного запроса; даже вызов инструмента моделью ничего не раскрывает.
- Установка на K8, сеть и секреты вне этого репозитория: задача в проекте home-infra.
- Один процесс приложения и SQLite достаточны для одного ребёнка и одного родителя; масштабирование вне v1.

## Допуск к исполнителям Codex и Cursor (#2415)

В приложении очередь и допуск хранятся в SQLite. В очередь записывается идентификатор
предметной операции. У вызова есть отдельный случайный ID, порядковый номер, хеш запроса
и привязка к записи расхода. Приложение сохраняет ID вызова и резерв лимита одной транзакцией
до отправки. Пауза и выделение следующей операции проверяются одной блокировкой SQLite.
Из очереди одновременно выполняется одна операция. Резерв отменяется только при явном ответе
об отказе до запуска. После потери подтверждения приложение сверяет прежний ID и хеш перед
использованием результата. Неизвестный исход блокирует новый dispatch и запасной канал.

Внутренний HTTP использует существующий ключ приложения и исполнителя. GET /status
сообщает имя канала, версию протокола и активность. GET /outcome/<id> возвращает подтверждение
строго для указанного вызова. Исполнитель хранит до 64 результатов в памяти и удаляет их
не позднее 10 минут. При заполнении кэша вытесняется самый старый результат. При отсутствии
подтверждения приложение показывает неопределённый
исход. В контрольных таблицах нет текста запросов или ответов. Вход ожидающего чата до
обработки лежит в предметной таблице и удаляется вместе с перепиской или по её сроку хранения.

Из существующего защищённого операторского доступа к контейнеру приложения:

- `python -m app.model.control pause` закрывает допуск и возвращает его ревизию.
- `python -m app.model.control status` сообщает queued, active, uncertain и состояние обоих
  исполнителей. `drained=true` требует `closed`, нулевого active и uncertain и подтверждения
  готовности обоих исполнителей с нулевой активностью. Ожидающие работы могут сохраняться.
- После переключения и проверки обоих исполнителей `python -m app.model.control resume
  --expect-revision N` открывает именно проверенную ревизию допуска. Повтор команды с N
  идемпотентен. Неопределённый результат запрещает resume. #2416 передаёт подтверждения через
  выделенный маршрут исполнителей и отличает `route_unavailable` до их вызова от
  `dispatch_unknown` после попытки.

Сборка #2415 поднимает схему 21 до 22 при старте. На рабочей schema18 сначала отдельно
принимается #2387. Для выпуска #2415 отдельно сохраняются согласованный backup SQLite и
пин образов приложения и исполнителей. До выката нужно остановить старые модельные входы,
установить отсутствие активных вызовов и проверить backup. После выката проверяются health,
ожидание, подтверждение и resume. Сетевое переключение #2416 проводится после появления
операторского контракта #2415 и не запускает миграций. Для отката остановить новые вызовы,
сохранить данные и очередь schema22, установить исход ранее принятых вызовов. Старый образ
можно вернуть с согласованной резервной копией прежней схемы. Очередь schema22 не должна
оставаться обработанной старым образом, который не поддерживает контроль допуска.
